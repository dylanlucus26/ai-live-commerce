### 修复的实际缺陷

此前安装版已能生成 RTMP，但持续运行后软件误显示“OBS 状态异常”，并暂停 AI 自动互动。
[诊断任务](https://github.com/dylanlucus26/ai-live-commerce/actions/runs/40675242414) 的安装版断言保留失败：
真实 OBS 仍 active，但产品会话变为 failed。不能将此前仅检查 OBS active 的按钮测试作为持续状态通过证据。

根因是单次连接的 RTMP 接收端在接受连接后不再监听端口，原检查只尝试新建 TCP 连接。
[FFmpeg 官方实现](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/network.c) 在接受连接后关闭监听 socket，保留已接受的连接。
产品现在先检查接收端本地地址/端口对应的 ESTABLISHED 连接，再检查监听可达性；不把发送端的客户端 socket 当作接收端。
检查不可观测时返回 undefined（不可观测），不将其计入两次连续确认缺失。

对应代码：[LocalTcpConnectionService.ts](https://github.com/dylanlucus26/ai-live-commerce/blob/7bd2bc1c424a0ae8095dda643896c3c11f72349a/electron/main/services/LocalTcpConnectionService.ts)、
[ReceiverReachabilityService.ts](https://github.com/dylanlucus26/ai-live-commerce/blob/7bd2bc1c424a0ae8095dda643896c3c11f72349a/electron/main/services/ReceiverReachabilityService.ts)、
[ObsStreamSession.ts](https://github.com/dylanlucus26/ai-live-commerce/blob/7bd2bc1c424a0ae8095dda643896c3c11f72349a/electron/main/services/ObsStreamSession.ts)。
这只证明本地传输连接存在，不证明解码或观众送达；后者仍由真实录制或平台侧证据验证。
