- 分支：`feat/v0.3.0-one-click-live`
- 基线：`main` 的 v0.2.6（`e33ddd21`）

## 两种启动模式

### 本地演练（推荐先验收）

1. 安装并开启 OBS Studio WebSocket v5（默认端口 4455）。
2. 导入商品和至少一张图片或视频。
3. 配置 MiMo API Key，选择 MiMo WAV 音色。
4. 设置 → 画面与 OBS：填写本机 OBS 端口、密码，确认有权使用后**保存为一键开播配置**。
5. 返回主控台，点击**本地演练**。
6. 软件自动检查 MiMo，启动/连接 OBS，创建专用画面源，把音频送入 OBS。
7. 预期：OBS 出现软件专用场景、图片/视频轮播、混音器可观察到声音；**不会连接抖音中控台，也不发送 StartStream**。
8. 点击**结束直播**，OBS 返回原场景，删除本次临时场景。
9. 重复测试商品切换、音频取消、应用关闭回收和再次启动。实机结果需记录。

### 开始直播（仅用于获授权的推流服务）

1. 完成上述首次配置，并在 OBS 中使用你有权限的直播服务或本地 RTMP 接收端。
2. 点击**开始直播**。
3. 软件先预生成 MiMo 开场语，再连接已登录的授权中控台、创建画面并向 OBS 发起 StartStream。
4. 只有 OBS 回报 active 且开场 WAV 获得播放完成回执，界面才进入 AI 直播运行态。
5. 关闭/异常时停止 AI 讲解、评论监听及本次拥有的 OBS 推流。
6. 必须独立检查：OBS 统计状态、接收端的视频轨/音频轨、声音实际可听、平台是否开播。

## 不能把下面这些当作已验收

- GitHub CI 上的 OBS 是 **本机模拟 WebSocket**，不是真的 OBS Studio。
- Chromium 页面测试可证明浏览器图片解码和 WAV 播放回执，不等于已验证 OBS 混音器或实际 RTMP 音频轨。
- 未使用真实 Douyin、DeepSeek/MiMo 付费账户和直播中控台的实际发言权限。
- 未进行 Windows/macOS 实机上的完整 OBS→本地 RTMP 接收与 FFprobe 音视频轨检查。
- 未进行 8–12 小时直播长时稳定性测试。
- macOS 采用 ad-hoc 签名测试构建，不等于正式 Apple 公证分发。
- 纯素材循环播放或无人值守商品分享不能被视作已满足抖音平台规则。

## 可复现实验命令

```bash
pnpm install --no-frozen-lockfile
pnpm exec tsc --noEmit
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm run test:browser-output
pnpm run test:smoke
pnpm run test:business
pnpm run test:layout
```

打包后另外运行 `test:electron` 与 `test:business:native`（设置 `ELECTRON_APP_PATH`）。

## 后续必须完成

1. 在真实 OBS Studio（Windows 和 macOS）实际创建场景，验证 Browser Source 的 `reroute_audio` 进入音频混音器。
2. 接入本地 RTMP 接收端，检查真实视频/音频流、启动/停止、断线重连与无声/黑屏。
3. 验证音频打断、商品轮换以及 2 小时/8 小时稳定性。
4. 处理真实平台开播/登录权限、主播值守与平台合规限制。
5. 对所有失败恢复及强制关闭场景完成实机验收后，再发布正式版本。

开发期间保持独立分支；**不得把模拟业务测试结果当作正式直播交付证据。**
